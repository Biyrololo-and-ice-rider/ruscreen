## Бизнес-акторы

| Актор | Описание роли |
|---|---|
| **Организатор** | Создаёт комнату, приглашает участников, управляет сессией |
| **Участник** | Присоединяется по ссылке, общается по вебкаме |

> Допущение: авторизация минимальная — имя + ссылка на комнату, без аккаунтов.

## User Stories

### Организатор

| ID | User Story |
|---|---|
| US-01 | Я, как организатор, хочу **создать комнату** одним кликом, чтобы быстро начать звонок без лишних настроек. |
| US-02 | Я, как организатор, хочу **получить ссылку-приглашение**, чтобы поделиться ею с участниками. |
| US-03 | Я, как организатор, хочу **завершить сессию для всех**, чтобы корректно закрыть встречу. |

### Участник

| ID | User Story |
|---|---|
| US-04 | Я, как участник, хочу **войти в комнату по ссылке**, указав своё имя, чтобы другие знали, кто я. |
| US-05 | Я, как участник, хочу **видеть и слышать** остальных, чтобы полноценно общаться. |
| US-06 | Я, как участник, хочу **включать/выключать камеру**, чтобы управлять своей приватностью. |
| US-07 | Я, как участник, хочу **включать/выключать микрофон**, чтобы не мешать фоновым шумом. |
| US-08 | Я, как участник, хочу **писать в текстовый чат**, чтобы общаться без голоса или делиться ссылками. |
| US-09 | Я, как участник, хочу **видеть чат от других** в реальном времени, чтобы не пропускать сообщения. |
| US-10 | Я, как участник, хочу **показывать свой экран**, чтобы демонстрировать материалы или рабочий стол. |
| US-11 | Я, как участник, хочу **видеть экран другого участника**, который его демонстрирует. |
| US-12 | Я, как участник, хочу **покинуть комнату**, чтобы завершить участие без ожидания других. |

## Acceptance Criteria

### US-01: Создание комнаты
1. На главной странице есть кнопка «Создать комнату» — без обязательной регистрации.
2. После нажатия генерируется комната с уникальным ID.
3. Организатор сразу попадает внутрь комнаты.

### US-02: Ссылка-приглашение
1. Внутри комнаты отображается ссылка вида `app.example.com/room/XXXX`.
2. Рядом со ссылкой есть кнопка «Скопировать».
3. При переходе по ссылке участник видит экран входа.

### US-03: Завершение сессии
1. У организатора есть кнопка «Завершить для всех».
2. Все участники получают уведомление и автоматически выходят.
3. Комната становится недоступной для новых подключений.

### US-04: Вход по ссылке
1. При переходе по ссылке отображается форма с полем «Ваше имя».
2. Поле имени обязательно — пустое имя блокирует вход.
3. После ввода имени и нажатия «Войти» участник подключается.
4. Если комната завершена — отображается сообщение об этом.
5. Если в комнате уже 4 участника — «Комната заполнена».

### US-05: Видео и аудио
1. Видеопотоки всех участников отображаются одновременно.
2. Под каждым видео — имя участника.
3. При выключенной камере — аватар/заглушка с именем.
4. Задержка аудио ≤ 300 мс в нормальных условиях сети.

### US-06: Управление камерой
1. Кнопка включения/выключения с визуальным индикатором.
2. При выключении другие видят заглушку.
3. Изменение — мгновенно, без перезагрузки.

### US-07: Управление микрофоном
1. Кнопка включения/выключения с индикатором.
2. При выключенном микрофоне другие не слышат звук.
3. Иконка «заглушен» у участника.

### US-08: Отправка сообщений
1. Панель чата доступна внутри комнаты.
2. Поле ввода + кнопка отправки (или Enter).
3. Пустое сообщение отправить нельзя.
4. После отправки поле очищается.

### US-09: Получение сообщений
1. Новые сообщения появляются в реальном времени.
2. Каждое сообщение содержит имя отправителя и время.
3. Чат автоматически прокручивается к последнему сообщению.

### US-10: Демонстрация экрана
1. Кнопка «Показать экран».
2. Браузер запрашивает разрешение на захват.
3. Экран транслируется остальным.
4. Одновременно шарить может только один участник.
5. Кнопка «Остановить демонстрацию».

### US-11: Просмотр демонстрации
1. При старте трансляции остальные видят её автоматически.
2. Демонстрация выделяется визуально (крупнее других потоков).
3. При остановке — интерфейс возвращается в обычный вид.

### US-12: Выход из комнаты
1. Кнопка «Покинуть комнату».
2. Участник отключается, остальные продолжают сессию.
3. Видео ушедшего исчезает у остальных.

## Открытые вопросы и допущения

❓ **Нужна ли авторизация / аккаунты?**  
💡 Нет. Вход — только имя + ссылка (как Google Meet без аккаунта).

❓ **Есть ли лимит на длительность сессии?**  
💡 Нет лимита — сессия активна до явного завершения. TTL Redis = 24 ч.

❓ **Нужна ли персистентность чата?**  
💡 Нет. Чат живёт только в рамках активной сессии.

❓ **Нужна ли запись звонка?**  
💡 Won't have в текущем скоупе.

⚠️ **Риск:** WebRTC требует STUN/TURN серверов для прохождения NAT — инфраструктурная зависимость.

⚠️ **Риск:** Одновременно экран шарит только один участник — ограничение, о котором стоит предупредить заказчика.
